What is it, and why does it exist?

Krypton is a minimal web browser for Windows. It opens tabs, has an address bar that completes what you type, a right-click menu, keyboard shortcuts, and a docs page — and deliberately almost nothing else. No accounts, no sync, no extensions store, no telemetry calling home, no 400 MB of JavaScript pretending to be a desktop app.

Why? Because every mainstream browser got heavy. I wanted something that starts fast, stays out of the way, and that I fully understand — every line of the window around the page is mine. If you've ever wished Chrome had a diet version, that's Krypton.

A real-life scenario: you're researching on a dozen tabs. Ctrl+T opens one, you type two letters and hit Tab to complete the site, Ctrl+W kills finished tabs, and when you inevitably close the wrong one, Ctrl+Shift+T brings it straight back. All keyboard, no mouse, no waiting.

How it's built

Three pieces, all plain and boring on purpose. The app is written in C# (.NET 8). The entire window you see — tab strip, toolbar, menus — is WinForms, real native Windows controls, which is why it starts fast and sips memory. The web pages themselves are rendered by Chromium, the same engine inside Chrome, embedded through a library called CefSharp.

What is CEF, exactly?

CEF stands for Chromium Embedded Framework. Think of it this way: Google's Chrome is two things glued together — the Chromium engine that renders pages, and Google's own window around it. CEF is just the engine part, packaged so other programs can borrow it. Krypton borrows the engine and builds its own window around it. You get Chrome-grade rendering and compatibility, while everything you click outside the page is 100% Krypton's own code.

A peek at the code

One rule runs the whole codebase: the web engine talks on background threads, Windows controls only tolerate the UI thread — so every event is marshalled across. It looks like this:

private void Browser_AddressChanged(object? sender, AddressChangedEventArgs e)
{
    // CEF thread: never touch controls here.
    Ui(() => addressBar.Text = e.Address); // marshalled to the UI thread
}

That's the pattern behind tabs, titles, favicons, loading bars, and every shortcut — small, explicit, no magic. The full source is on GitHub under MIT.

System requirements

Minimum — Windows 10 (1809+, 64-bit), dual-core x64 processor, 4 GB RAM, ~800 MB free disk, and the VC++ 2022 x64 runtime.

Recommended — Windows 11 (64-bit), quad-core or better, 8 GB RAM, an SSD, and a 1080p+ display. Extra RAM mostly matters when lots of heavy tabs (video, maps, docs) stay open.

Build it yourself

You need Windows 10/11 x64, Git, the .NET 8 SDK, and the VC++ 2022 x64 runtime. Then:

git clone https://github.com/CodeVynix/Krypton.git
cd Krypton
dotnet build
dotnet run --project Krypton\Krypton.csproj

Keep the project on x64 (CefSharp supports nothing else — AnyCPU won't run), and close Krypton before rebuilding or the running exe locks its own files. For a release build:

dotnet publish Krypton\Krypton.csproj -c Release -r win-x64 --self-contained true -o publish

Ship the whole publish folder; compile Krypton.iss with Inno Setup for the installer. Never single-file publish — CefSharp needs its native DLLs next to the exe.
