# Code Signing Policy

Krypton signs and distributes release artifacts. This document describes the signing method and process.

## Windows — SignPath Foundation (pending)

We are applying to the SignPath Foundation program for free code signing of Windows release artifacts.

Planned statement (required by the program, once approved):
> Free code signing provided by SignPath.io, certificate by SignPath Foundation

**Status:** Pending approval.

### What will be signed

- The Windows installer package (`KryptonSetup-<version>.exe`), produced by Inno Setup, published on GitHub Releases.

### Build and signing process

- Artifacts are built from this repository (github.com/CodeVynix/Krypton) using GitHub Actions CI.
- Only CI-built artifacts are submitted to SignPath for signing — local/manual builds are never signed.
- The signing private key is held by SignPath (HSM-backed). This project never stores or has access to the private key.

### Team roles (single-maintainer project)

- **Authors** (commit access, can modify the repository without additional review):
  - https://github.com/CodeVynix
- **Reviewers** (review required for changes proposed by non-authors): none at this time — external contributions, if any, require author review before merge.

Both GitHub and SignPath accounts for the above use multi-factor authentication.
